4. Cell 4: Clean + Feature Engineering

This is the most important transformation cell.

4.1 Duplicates

What:
Duplicates are counted and reported, but kept.

Why:
Each row represents a user session; identical rows can still be valid sessions.
You requested not to remove them.

4.2 Boolean normalization

What:
Weekend and Revenue mapped to numeric 0/1 using bool_map.

Why:
Models need numeric target/features.
Handles variations like "TRUE", "False", Python True/False, and 0/1 safely.

4.3 Month numeric mapping

What:
Month converted to Month_num.

Why:
Needed to build cyclic seasonal features.

4.4 Engineered features (from your doc/spec intent)

What:
TotalSessionDuration = sum of three duration columns
ProductInfoRatio = ProductRelated / (Informational + 1)
EngagementScore = PageValues / (TotalSessionDuration + 1)

Why:
Captures richer behavior patterns:
total browsing time
shopping intent focus
value-per-time signal
+1 avoids divide-by-zero errors and keeps stable values.

4.5 Cyclic seasonality

What:
Created:
Month_sin
Month_cos
Then removed Month_num and original text Month.

Why:
Month is cyclic (Dec is close to Jan).
Sin/cos encode cyclic distance correctly.
Dropping text Month prevents numeric pipeline errors ('Feb' string in median imputer), which you hit and we fixed.

4.6 Final safety checks

What:
Ensured target has no missing values.
Cast Revenue and Weekend to integer.

Why:
Guarantees clean target and stable downstream model behavior.


5. Cell 5: Build Preprocessing Pipeline

What was done:
Split into:
X (features)
y (target)
Defined feature groups:
Categorical: VisitorType, OperatingSystems, Browser, Region, TrafficType
Numerical: all remaining columns (including engineered and cyclic month features)
Created two pipelines:
numeric: median imputation + standardization
categorical: most-frequent imputation + one-hot encoding
Combined with ColumnTransformer.

Why:
Different data types need different preprocessing.
Numeric scaling helps many ML algorithms.
Categorical one-hot encoding avoids false numeric ordering (very important for columns like Region and OperatingSystems).

How:
Pipeline(...) for each branch.
ColumnTransformer(...) to apply both in one reusable object (preprocessor).
